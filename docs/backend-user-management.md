# Backend User Management Module

Admin Phase 5B implements tenant user management for `COMPANY_ADMIN` users.
`SUPER_ADMIN` users manage tenants from Platform screens, and tenant roles below
company admin do not manage users.

## Implemented APIs

```http
GET    /api/v1/users?search=&role=&status=&departmentId=&page=&limit=
POST   /api/v1/users
GET    /api/v1/users/:id
PATCH  /api/v1/users/:id
POST   /api/v1/users/:id/activate
POST   /api/v1/users/:id/deactivate
POST   /api/v1/users/:id/reset-password
```

## User Fields

```text
id
uuid
companyId
departmentId
departmentName
name
email
phone
role
companyRole
status
mustChangePassword
createdAt
updatedAt
```

## Rules

Tenant user roles are:

```text
COMPANY_ADMIN
EMPLOYEE
MANAGER
PROCUREMENT
FINANCE
```

`SUPER_ADMIN` is rejected by tenant user management. Department assignment is
optional for `COMPANY_ADMIN` and required for other tenant roles. Temporary
passwords are generated by the backend, returned once, stored only as bcrypt
hashes, and force `mustChangePassword=true`.

## Related Frontend Data

The `/users` admin screen also reads:

```http
GET /api/v1/departments
GET /api/v1/company-roles
```

Departments power the assignment dropdown. Company roles power the optional
company role selector while system role remains the required tenant role.
